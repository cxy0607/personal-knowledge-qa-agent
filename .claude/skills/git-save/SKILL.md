# Git Save 技能（带质量门禁 · 项目专用版）

本项目专用版，比全局版多一步：**提交前先派两个检查员做质量门禁，全部通过才提交**。

另外项目已配置自动门禁：Claude 执行 `git commit` 时会被自动拦截并做快速检查（后端 pytest + Python 语法编译检查），这是最后一道保险，正常情况会放行。

## 执行步骤

### 第一步：看看改了啥

1. 运行 `git status` 查看有哪些修改
2. 用大白话给用户列一份「改动清单」
3. 留意不该提交的文件（.env、.venv、__pycache__、logs、.claude/gate/ 等）——它们已被 .gitignore 自动排除，不用慌，但发现新的可疑文件要提醒用户
4. 没有任何修改 → 直接告诉用户「没有需要保存的修改」，结束流程

### 第二步：测试门禁（派 tester1）

用 Task 工具派发 tester1，任务说明必须包含「以门禁模式运行」并说明检查目的：

- 返回 `门禁判定: PASS` → 继续第三步
- 返回 `门禁判定: FAIL` → **立即停止，不提交**。把 tester1 报告的问题用大白话转述给用户，建议「先修好再提交」，并可主动提出让 tester1 用普通模式修复

### 第三步：质量门禁（派 quality-engineer）

同样用 Task 工具派发 quality-engineer，任务说明包含「以门禁模式运行」：

- 返回 `门禁判定: PASS` → 继续第四步
- 返回 `门禁判定: FAIL` → **立即停止，不提交**，转述问题与修复方向

### 第四步：生成提交信息并请用户确认

1. 根据改动生成中文提交信息，格式 `类型: 做了什么`（feat / fix / docs / style / refactor / chore）
2. 展示「将要保存的内容」+ 提交信息，**等用户确认后再继续**

### 第五步：提交并推送

1. `git add .`
2. `git commit -m "提交信息"`（会自动触发快速门禁：后端 pytest + Python 语法编译检查，通常几十秒）
3. 如果自动门禁把提交拦下 → 把拦截提示翻译给用户，回到修复流程，不要反复重试
4. `git push`；推送失败（网络问题、没有远程仓库）就告诉用户「代码已经保存在本地电脑上了，等网络恢复再推」，不要慌

## 重要规则（继承全局版）

- 必须先展示再执行，等用户确认
- 提交信息用中文
- 不提交敏感文件
- 推送失败不慌
- **推送前必须做隐私审计**：用户明确要求过，推送前检查 .env 未跟踪、代码中无 API key/密码/个人信息（详细清单见 security-audit 技能）
- **逃生门**：极特殊情况（如用户赶时间）可告诉用户存在 `git commit --no-verify -m "..."` 跳过自动检查的办法，但要说明「跳过了检查，有风险，慎用」

## 提交信息类型参考

| 前缀 | 含义 |
|------|------|
| feat | 新功能 |
| fix | 修 bug |
| docs | 改文档 |
| style | 调样式 |
| refactor | 重构代码 |
| chore | 杂项维护 |
